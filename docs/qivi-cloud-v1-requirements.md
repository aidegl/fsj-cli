# qivi 云端化 V1.0 需求文档

> 编写：52小风｜2026-11-26｜决策依据：东城四问四答（本文档第二节，答案原文为准）
> 部署目标：云端服务器 8.155.148.75（OpenClaw 协助部署）

## 一、背景与目标

qivi 小人（粒子渲染+语音交互）从本地部署升级为云端部署：任意电脑/设备打开同一云端页面，看到同一个小人；小人具备**说话（口型+粒子随音波震动）**与**听（语音监听/唤醒）**能力。各 agent 的情绪与语音事件经云端汇聚，驱动小人实时反应。

**已验证能力（直接继承，不重新开发）**：
- 粒子随音波震动：本地 Web Audio 逐帧分析正在播放的音频振幅，驱动粒子位移（60fps 本地实时，声画天然同步）——qivi-dock 现役实现，取证（AudioContext/createAnalyser/getByteFrequencyData 三件套在役）
- 渲染分层：云端只发轻量指令（几字节）+ 音频文件下发；**粒子渲染永远在观看端本地**，云端不渲染任何画面帧

## 二、决策记录（东城四答，2026-11-26）

| 问题 | 东城答案 | 设计含义 |
|---|---|---|
| 小人形态 | **先一个，预留多小人架构**（前期简单，后面一个 agent 对应一个形象） | 事件协议所有字段带 agentId（V1 前端聚合渲染，多小人 V2 直接启用） |
| 表情触发 | **1.0 不需要情绪系统**——先嘴巴能动+粒子随声音震动；无意识/潜意识系统出来后由无意识控制 | V1 驱动源=音频振幅（口型/震动），情绪事件协议预留但前端不实现 |
| 语音模式 | **监听模式或手动触发**：监听用唤醒词开启对话（防噪音耗算力）；一段时间无声→不思考但保持监听 | 双模式并行：唤醒词检测（本地轻量）+ 按键说话；静默回监听态 |
| TTS 音源 | **豆包语音**（火山引擎） | 新接入：火山引擎 TTS API（需 AK/SK 或 API Key 配置）；MiniMax/cosyvoice 不用 |

## 三、V1.0 范围

### 做（V1.0 交付）

1. **云端页面**：qivi 小人渲染页（复用 qivi-dock 粒子内核）托管云端 nginx HTTPS，任意设备浏览器打开同一 URL 看同一小人
2. **说话（TTS 链）**：agent 文本 → 豆包 TTS → 音频流回页面 → 本地播放 + 口型开合 + 粒子随音波震动（全部本地实时）
3. **听·监听模式**：页面持续本地采集麦克风 → **本地唤醒词检测**（轻量模型，CPU 占用低）→ 唤醒词命中 → 录音上传 → ASR 转文字 → LLM → 豆包 TTS 回播；静默超时（可配，如 30s）→ 回监听态（只听唤醒词，不思考）
4. **听·手动模式**：按住页面按钮说话（免唤醒词），松开即送 ASR——与监听模式并存切换
5. **LLM 接入**：默认 qwen3:14b（本机快思考），可配置切换其他模型
6. **云端部署**：页面静态托管 + WS/信令服务 + TTS/ASR 调用代理，全部落 8.155.148.75（pm2 常驻）

### 不做（V1.0 边界，后续版本）

- 情绪/表情系统（待无意识+潜意识系统建成后由无意识驱动）
- 多小人同屏（架构预留：事件协议带 agentId）
- 外部事件联动（邮件触发表情等）
- WebRTC 实时全双工（V1 用轮次式：说→识别→答，全链 2~5s 可接受）

## 四、架构

```
[任意设备浏览器]
  页面：qivi 粒子渲染 + 唤醒词检测(本地) + 麦克风采集 + 音频播放 + AnalyserNode 振幅→粒子
     │ HTTPS/WSS（云端 nginx）
     ▼
[云端 8.155.148.75]
  ├─ 页面静态托管（nginx）
  ├─ 信令/广播 WS（node，pm2 常驻）：会话事件/文本流转
  ├─ 语音编排服务（node）：ASR 调用 → LLM(qwen3:14b 或配置) → 豆包 TTS → 音频流回页面
  └─ （复用）A2A 信箱：agent 侧文本/事件来源

[Windows 主机] ollama qwen3:14b（LLM 算力，本机）
[豆包/火山引擎] TTS API（云端调用）
[Mac mini] 与任意新设备：开同一页面即同一个小人
```

**音频驱动震动（核心已验证）**：页面本地播放豆包 TTS 音频的同时，AnalyserNode 逐帧（16ms）分析播放中音频的振幅 → 粒子位移=f(振幅) → 声画同步零额外延迟。网络只传音频文件/流，不传任何渲染帧。

## 五、关键实现要点

1. **唤醒词**（监听模式核心）：本地轻量检测（候选：openWakeWord / Porcupine，CPU 占用 <2%）；唤醒词自定义（如"qivi"）；命中后进入对话态，静默 N 秒回监听
2. **ASR**：豆包/火山 ASR 或 FunASR（实施时按音质/成本定，候选记录在案）
3. **豆包 TTS**：火山引擎 API；音色、语速可配置；API Key 走本地配置文件（gitignore，密钥三闸）
4. **多小人预留**：所有事件（情绪/语音/文本）payload 带 agentId；V1 前端聚合渲染单形象，V2 按 agentId 分流多形象
5. **浏览器授权**：麦克风每设备首次授权一次（HTTPS 前提已满足）；喇叭播放需首次页面交互激活
6. **监听模式的算力纪律**：静默期只跑本地唤醒词检测（<2% CPU），不调 ASR/LLM——不思考但保持监听

## 七、验收标准（V1.0）

1. Windows/Mac 两台浏览器打开同一云端 URL → 看到同一个小人
2. 对 Windows 页面说话（手动模式）→ 转文字 → qwen 回答 → 豆包语音从小人喇叭播出 + 口型动 + 粒子随音波震动
3. 监听模式：说唤醒词 → 进入对话态；静默 30s → 回监听态；监听期 CPU 占用 <5%
4. 手动/监听模式可切换
5. 关闭 Windows 会话（小风聊天窗口不在）→ 常驻进程照常工作（无人值守验证）
6. 断网重连 → 会话自动恢复、消息补收不丢
